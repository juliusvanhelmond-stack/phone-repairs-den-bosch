# Phone Repairs — redesign (JUNE Studio)

Next.js 16 (App Router, Cache Components) + TypeScript + Tailwind v4 site for Phone Repairs Den Bosch.
Phase 1 demo; the live site www.phonerepairs.nl is never modified. Read AGENTS.md: this Next.js
version differs from older training data — check `node_modules/next/dist/docs/` before using an API.

## Commands
- `npm run dev` / `npm run build` (runs `validate:data` first) / `npm start`
- `npm run check` — typecheck, lint, data validation, parser test
- `npm run test:smoke` — Playwright E2E + axe against a running server (`BASE_URL`, default :3000)
- `npm run screenshots` — full-page screenshots at 375/768/1024/1440 into docs/screenshots
- `npm run migrate` — discover → fetch → parse → analyze → report (see docs/migration-plan.md)

## Architecture
- `src/types/content.ts` — zod schemas = the content model (brands, devices, repairs, prices, FAQ, claims, URL inventory).
- `src/data/*.json` — content. `devices/*.json` is generated by `npm run catalog:seed`; edit the generator, not the JSON.
- `src/lib/catalog.ts` — validated data + lookups; the only way components read content.
- `src/lib/site.ts` — contact details and env flags (`isDemo`, `allowIndexing`).
- Reviews: Google via the client's Trustindex widget (`site.reviews`), Kiyoh via `site.kiyoh`. The Kiyoh score/count are fetched before each build by `npm run reviews:fetch` (needs `KIYOH_FEED_HASH`, a secret) into the git-ignored `src/data/generated/kiyoh.json`; without it the badges show a plain link. Don't fetch reviews at runtime with `"use cache"`: it made client prefetches hang.
- Two languages (`src/lib/i18n.ts`). All pages live under `src/app/[lang]` with Dutch folder names; `src/proxy.ts` rewrites public URLs to them. Dutch keeps the original unprefixed URLs (`/nl/*` 308s to `/*`); English lives under `/en` with translated segments (`/en/repairs`, `/en/repair/screen-replacement`, `/en/faq`, …; landing, brand, device and blog slugs stay Dutch). Unknown URLs get a real 404: the proxy fetches the static `[lang]/niet-gevonden` page and returns it with status 404.
- Code and data always use Dutch paths; `Link` from `@/components/i18n/link` localizes them (never wrap its href in `href()` again). UI strings are co-located as `t("nl", "en")` (`getI18n()` in server components, `useI18n()` in client components). Content translations live in `src/data/translations/en.json` and are applied with the `localize*` helpers in `catalog.ts`; `validate:data` fails when a record has no English entry. `pageMetadata` needs `locale` and sets canonical + hreflang. The language switch is a plain `<a>` (cross-locale prefetch loops the router).
- `src/app/[lang]` routes: `/`, `/reparaties`, `/reparaties/[brand]`, `/reparaties/[brand]/[model]`, `/reparatie/[repair]`, info pages; `sitemap.ts` (both languages with alternates) and `robots.ts` stay at the `src/app` root.
- Pages that keep their original URL live in `src/data/landing-pages.json` (area pages, Nintendo Switch, pre-owned, FAQ topics) and render through `src/app/[lang]/[page]` and `src/app/[lang]/veelgestelde-vragen/[topic]` with `LandingTemplate`; blog posts in `src/data/blog.json` under `/blog-post/[slug]`. Static routes are listed in `src/lib/routes.ts`; `src/proxy.ts` 404s every unknown dynamic path.
- Dynamic routes use `generateStaticParams` + `notFound()` and `export const instant = false` (real 404s, fully static pages).
- `src/components/{layout,home,devices,repairs,forms,ui,motion}`; UI primitives follow shadcn/ui conventions on `radix-ui`.
- Device cards, device pages and the finder show one licensed product photo per device type on white (`DevicePhoto`, `src/assets/devices/`, mapping in `devicePhotoKey`); they are examples of the type, never presented as the exact model. Foldables and small list icons use the SVG render (`DeviceArt`). Atmosphere photos (hero, about, process band, CTA) are licensed Adobe Stock images in `src/assets/photos/`, listed in docs/image-credits.md; add new photos there too and never present stock photos as the shop itself.
- `src/components/iphone/` — homepage 3D exploded-view section (React Three Fiber). `parts.ts` is the single source for part offsets, scroll windows, labels and repair links; `model.tsx` swaps the procedural stand-in for a licensed GLB via `NEXT_PUBLIC_IPHONE_MODEL_URL` (spec: docs/3d-model-requirements.md). The WebGL bundle is lazy-loaded; no-WebGL and reduced-motion fallbacks must keep working.
- `scripts/{discovery,migration,validation,lib}` — migration pipeline and QA tooling (run with tsx).

## Content-preservation rules (non-negotiable)
1. Never invent prices, warranty terms, reviews, ratings, opening hours or appointment slots.
2. Every record from the old site keeps its source URL (`sources[]`, `legacyUrls[]`); unknown fields go to `extra`.
3. A price is shown only if `verified: true` with a `verified-source`/`owner-confirmed` source (`getVerifiedPrice`). Otherwise "Op aanvraag".
4. Public claims/FAQs need a non-demo source on phonerepairs.nl (`npm run validate:data` enforces this).
5. Demo-only content is marked with `DemoNote` and disappears with `NEXT_PUBLIC_DEMO_MODE=false`.
6. Changed URLs get a 301 via `src/data/url-inventory.json`. Keep original URLs where practical.
7. The site stays noindex until `NEXT_PUBLIC_ALLOW_INDEXING=true` is set for the approved launch.
8. The appointment form must never claim a booking was sent while no backend is connected.
9. The 3D stand-in phone is not an accurate iPhone 17 teardown and must stay labelled as temporary in demo mode until a licensed model is supplied.

## Conventions
- Dutch UI copy, informal "je". English code and comments.
- Contact priority (client requirement): WhatsApp first, then phone (073 822 0013, same number), e-mail last. Use `ContactActions` for CTA rows, `WhatsAppCard` for in-page prompts and `whatsappHref(whatsappMessage({ device, repair }))` for prefilled links; the floating `WhatsAppWidget` opens by itself once per session. The widget copy in `site.whatsapp` is verbatim from the current site.
- House style (client requirement): green `#106f31` (`accent`), grey `#515151` (`muted`), dark `#222222` (`ink`, `night`), typeface Open Sans. The official logo goes in `public/brand/` and is switched on via `site.logo` in `src/lib/site.ts`; until then a placeholder mark is shown.
- Design tokens live in `src/app/globals.css` (`@theme`); use `text-ink`, `text-muted`, `bg-mist`, `text-headline`, etc. — no raw hex in components. The page base is a neutral tint (`canvas`); cards are `bg-white`; use `<Aura>` for soft colour fields and the `glass` / `glass-dark` utilities for frosted surfaces. Green text on tints uses `text-accent-strong`; on dark backgrounds `text-accent-light`.
- Server Components by default; `"use client"` only for interaction (header, finder, form, exploded phone).
- Respect `prefers-reduced-motion`; reveal-on-scroll is CSS (`.reveal`), content is never hidden without JS.
